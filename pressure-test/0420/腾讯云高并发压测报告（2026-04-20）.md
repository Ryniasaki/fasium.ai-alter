# 腾讯云高并发压测报告（2026-04-20）

## 1. 测试目的

验证在前一轮压测优化之后，腾讯云 `8c16g` 服务器在更高并发下的稳定性、延迟表现和任务流可用性。

## 2. 测试配置

| 项目 | 配置 |
| --- | --- |
| 测试目标 | `http://127.0.0.1:8081` |
| 测试工具 | `k6` |
| 读接口并发 | `8 VUs` |
| 改款链路并发 | `8 VUs` |
| 取版链路并发 | `4 VUs` |
| 总并发上限 | `20 VUs` |
| 持续时间 | `90s` |
| 任务超时 | `90000ms` |
| 轮询间隔 | `1s` |

## 3. 测试结论

这轮高并发测试**没有通过稳定性目标**。

结果表现为：

- 读接口开始出现超时
- `complete_image_edit` 和 `complete_pattern_extract` 开始超时
- 整体请求失败率显著上升
- `http_req_duration` 的 `p95` 已经顶到 `1m`

说明前一轮优化后，系统在低压和中压下已经可用，但在 `20 VUs` 这一档已经明显超过了当前可稳定承载范围。

## 4. 核心结果

| 指标 | 结果 |
| --- | ---: |
| 总请求数 | `61` |
| 请求失败率 | `32.78%` |
| 检查通过率 | `67.21%` |
| 平均请求延迟 | `23.59s` |
| `p95` 请求延迟 | `1m` |
| `read_only_success_rate` | `0%`（本轮出现超时） |
| `redesign` 任务链路 | 出现超时，未形成稳定 E2E 成功 |
| `extract` 任务链路 | 出现超时，未形成稳定 E2E 成功 |

## 5. 失败症状

本轮压测主要出现以下问题：

- `GET /auth/me` 发生请求超时
- `POST /proxy/complete_image_edit` 发生请求超时
- `POST /proxy/complete_pattern_extract` 发生请求超时
- 任务提交后，k6 侧出现 `body is null`，说明请求已经在服务端超时或未返回有效响应
- 约在 `1m08s` 左右开始出现明显的 timeout 日志

## 6. 与上一轮对比

上一轮 `5 VUs` 的短压测：

- `http_req_failed = 0.00%`
- `p95 = 206.38ms`
- `read_only_success_rate = 100%`
- `redesign_e2e_success_rate = 100%`
- `extract_e2e_success_rate = 100%`

本轮 `20 VUs` 的高压测试：

- 成功率明显下降
- 延迟显著上升
- 读接口和任务接口都开始超时

结论很直接：

- 当前优化**确实改善了低中压场景**
- 但在 `20 VUs` 这一档，系统仍然会被压到超时

## 7. 结论

这台腾讯云 `8c16g` 服务器在当前架构和压测模式下：

- `5 VUs` 左右表现稳定
- `20 VUs` 已经明显失稳
- 压测瓶颈仍然集中在 `tenant-service` 的高并发请求处理和任务链路

下一步如果要继续提升上限，优先级仍然是：

1. 降低轮询压力
2. 继续压缩只读接口和任务接口的开销
3. 再考虑更激进的任务状态推送化
