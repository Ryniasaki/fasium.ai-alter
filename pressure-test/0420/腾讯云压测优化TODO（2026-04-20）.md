## 已完成

- [x] 降低任务轮询频率
  - 说明：`POLL_INTERVAL_SECONDS` 在腾讯云部署和 runninghub 默认值里已提升到 `8s`，减少了高并发下的轮询放大效应。
  - 验收：压测时任务轮询请求密度下降，任务链路的 p95 延迟更稳定。

- [x] 给 `auth/me` 加短 TTL 缓存
  - 说明：`get_current_user` 和 `/auth/me` 已接入短 TTL 缓存，重复请求会复用同一份用户快照。
  - 验收：只读场景下数据库查询次数下降，接口延迟更稳定。

- [x] 给 `metrics` 接口加缓存
  - 说明：`/metrics` 已加短 TTL 缓存，避免频繁重建 Prometheus 输出。
  - 验收：压测时 `metrics` 请求延迟下降，指标导出开销减小。

- [x] 历史列表接口分页和字段裁剪
  - 说明：历史接口已补充页面大小上限控制，并结合缓存降低了重复查询压力；列表仍保留前端所需的基础字段。
  - 验收：`/proxy/tasks/history` 在高并发下的耗时下降。

- [x] 降低高频路径日志级别
  - 说明：服务日志默认级别改为 `INFO`，降低轮询和高频查询路径的日志噪音。
  - 验收：高并发下 CPU 和磁盘 IO 压力下降。

- [x] 状态查询引入 Redis 缓存
  - 说明：任务状态查询已接入缓存，短时间内重复轮询会优先命中缓存，减少对 PostgreSQL 和上游的重复压力。
  - 验收：轮询请求对 PostgreSQL 的直接压力明显减少。

- [x] 给数据库热点表加索引
  - 说明：为 `tenant_task_records` 和 `tenant_projects` 补充了历史查询和状态查询常用复合索引。
  - 验收：查询耗时下降，慢查询减少。

- [x] worker 与 tenant-service 资源隔离
  - 说明：腾讯云 compose 已为 tenant-service、worker、runninghub、frontend、redis 配置 CPU 配额，减少 worker 抢占 tenant-service 的 CPU。
  - 验收：worker 繁忙时，tenant-service 的 p95 延迟不再明显抖动。

- [x] 压测前补齐监控 exporter
  - 说明：已加入 node-exporter、cAdvisor、redis-exporter、postgres-exporter，并接入 Prometheus。
  - 验收：压测报告能直接给出 CPU / 内存 / DB / Redis 的完整曲线。
